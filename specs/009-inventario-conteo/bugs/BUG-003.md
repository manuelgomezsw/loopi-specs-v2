**Patched**: 2026-07-13

## Descripción

La migración de base de datos `014_crear_tabla_inventarios.up.sql` intenta crear una restricción de clave foránea (foreign key) desde `inventarios.responsable_id` hacia la tabla `usuarios (id)`:

```sql
CONSTRAINT fk_inventarios_responsable FOREIGN KEY (responsable_id) REFERENCES usuarios (id)

```text

**Problema**: La tabla `usuarios` **no existe** en la base de datos. Esto causa un error SQL al ejecutar la migración:

```text
Error 1215: Cannot add foreign key constraint (table `usuarios` does not exist)

```text

**Tabla correcta**: Según la arquitectura del proyecto, los responsables de inventarios son `empleados` (rol: admin, lider_tienda, barista). La tabla `empleados` existe desde la migración 003 y tiene una columna `id` BIGINT UNSIGNED.

**Referencia correcta**: `CONSTRAINT fk_inventarios_responsable FOREIGN KEY (responsable_id) REFERENCES empleados (id)`

## Análisis de Causa Raíz

### Problema Identificado

En `/home/manuelgomezjp/repos/loopi-v2/loopi-api-v2/migrations/014_crear_tabla_inventarios.up.sql` línea 19:

```sql
CREATE TABLE inventarios (
  id              BIGINT UNSIGNED  NOT NULL AUTO_INCREMENT,
  tienda_id       BIGINT UNSIGNED  NOT NULL,
  fecha           DATE             NOT NULL,
  tipo            ENUM('diario','semanal','mensual','inicial') NOT NULL,
  horario         ENUM('apertura','mediodia','cierre') NULL,
  horario_norm    VARCHAR(10)      GENERATED ALWAYS AS (COALESCE(horario, '')) STORED,
  estado          ENUM('en_progreso','completado') NOT NULL DEFAULT 'en_progreso',
  responsable_id  BIGINT UNSIGNED  NOT NULL,
  iniciado_en     DATETIME         NOT NULL,
  completado_en   DATETIME         NULL,
  creado_en       DATETIME         NOT NULL,
  actualizado_en  DATETIME         NOT NULL,

  PRIMARY KEY (id),
  CONSTRAINT uq_inventarios_tienda_tipo_horario_fecha
    UNIQUE (tienda_id, tipo, horario_norm, fecha),
  CONSTRAINT fk_inventarios_tienda FOREIGN KEY (tienda_id) REFERENCES tiendas (id),
  CONSTRAINT fk_inventarios_responsable FOREIGN KEY (responsable_id) REFERENCES usuarios (id)  ← ERROR AQUÍ
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

```text

**La tabla `usuarios` no existe en la base de datos.**

**Tablas que sí existen** (según migrations):

- `tiendas` (migration 002): ✅ Existe — usada correctamente en línea 18

- `empleados` (migration 003): ✅ Existe — tiene estructura `id, nombre, apellido, usuario, rol, tienda_id, ...`

**Por qué ocurrió**:

1. Probablemente fue un copy-paste error de otro módulo (auth o similar) donde se usa `usuarios`
2. O fue un mala interpretación del modelo conceptual ("responsable es un usuario" → "REFERENCES usuarios")
3. No se verificó que la tabla referenciada existiera antes de crear la migración
4. Las tareas T004 y T005 fueron marcadas como ✅ completas sin validar que las migraciones efectivamente ejecuten

### Validación Cruzada

Comparando con otros módulos:

- **Módulo tiendas** (migration 002): Referencia `tiendas (id)` ✅ Tabla existe

- **Módulo empleados** (migration 003): FK a `tiendas (id)` ✅ Tabla existe

- **Módulo items** (migration 011): FK a `tiendas (id)` ✅ Tabla existe

- **Módulo inventarios** (migration 014): FK a `usuarios (id)` ❌ **Tabla NO existe**

## Notas Adicionales

- **Modelo de datos**: No hay archivo `data-model.md` separado en el directorio de specs. Se recomienda crear uno para documentar las relaciones entre tablas explícitamente, incluyendo migraciones.

- **Lecciones aprendidas**:

  - Task completion ("T004 ✅ Completa") no debería marcar tareas como completas sin validación de ejecución real

  - Las migraciones de base de datos deben ser testeadas localmente antes de merge

  - Necesario agregar a pre-commit hook: validación de que las migraciones son sintácticamente correctas y referencian tablas que existen

- **Dependencia arquitectónica**: La arquitectura de Loopi v2 usa `empleados` como entidad de usuarios de aplicación (con roles). Cualquier nuevaforeignkey a "usuarios del sistema" debe referenciar `empleados (id)`, no a una tabla fantasma `usuarios`.
