## Descripción

Al intentar iniciar un conteo desde el frontend (POST /inventarios), el servidor responde con un error **400 Bad Request**. El usuario no puede iniciar un segundo conteo de la misma tienda/tipo/horario en la misma fecha.

**Log del backend** (evidencia real):

```text
2026/07/13 10:43:13 INFO inventario.iniciar.post: iniciando tienda_id=1 tipo=diario horario=0x1e10f3268890
2026/07/13 10:43:13 INFO inventario.iniciar: iniciando tienda_id=1 tipo=diario
2026/07/13 10:43:14 ERROR inventario.iniciar: error creando tienda_id=1 error="error creando inventario: Error 1062 (23000): Duplicate entry '1-diario-apertura-2026-07-13' for key 'inventarios.uq_inventarios_tienda_tipo_horario_fecha'"
2026/07/13 10:43:14 ERROR inventario.iniciar.post: error error="error creando inventario: Error 1062 (23000): ..." tienda_id=1

```text

**Problema identificado**:

- **UNIQUE constraint violation**: `(tienda_id=1, tipo=diario, horario=apertura, fecha=2026-07-13)`

- **HTTP status**: 400 Bad Request ❌ (debería ser 409 Conflict)

- **Mensaje de error**: Genérico, sin información útil ❌ (debería mencionar `conteo_duplicado`)

- **Según spec**: El sistema debe bloquear conteos duplicados (RF-INV-01.4) ✅, pero con error code correcto

**Comportamiento esperado**:

- Servidor responde **409 Conflict** (no 400)

- Mensaje incluye `error: "conteo_duplicado"` per spec contracts/api.md

- Usuario recibe mensaje claro: "Ya existe un conteo activo para esta tienda, tipo y horario hoy"

**Comportamiento observado**:

- Servidor responde 400 Bad Request

- Mensaje es error MySQL raw: `"Duplicate entry '1-diario-apertura-2026-07-13'..."`

- Usuario no sabe qué hacer

## Análisis de Causa Raíz

### Problema Identificado

En `repository.go` (CreateInventario), el INSERT genera error de UNIQUE constraint:

```sql
Error 1062 (23000): Duplicate entry '1-diario-apertura-2026-07-13'
  for key 'inventarios.uq_inventarios_tienda_tipo_horario_fecha'

```text

**Lo que sucede**:

1. Usuario intenta POST /inventarios con tienda_id=1, tipo=diario, horario=apertura, fecha=2026-07-13
2. Base de datos rechaza porque **ya existe un inventario con esa combinación**
3. Repository retorna error MySQL raw: `"Error 1062: Duplicate entry..."`
4. Service pasa error al handler
5. Handler retorna error con HTTP 400 (ver línea 74 de handler.go):

```go
resp, err := h.service.Iniciar(ctx, &req, userID, roleID)
if err != nil {
  h.logger.ErrorContext(ctx, "inventario.iniciar.post: error", "error", err.Error(), ...)
  h.respondError(w, http.StatusBadRequest, "error", err.Error())  // ← HTTP 400 ❌
  return
}

```text

### El Problema Real

El backend **detecta correctamente que hay un duplicate** (UNIQUE constraint trabajando bien ✅), pero:

1. **Status Code incorrecto**: Retorna `400 Bad Request` en lugar de `409 Conflict`

   - 400 significa "request malformado"

   - 409 significa "conflicto con estado existente" (exactamente este caso)

2. **Mensaje no cumple spec**: Retorna error MySQL raw en lugar de formato spec

   - Actual: `"error": "error creando inventario: Error 1062 (23000): Duplicate entry..."`

   - Esperado (per spec contracts/api.md): `"error": "conteo_duplicado", "mensaje": "Ya existe un conteo en progreso para esta tienda, tipo y horario hoy"`

3. **No distingue entre tipos de error**: Todos los errores de CreateInventario retornan 400

   - Validation error → 400 ✅ (correcto)

   - Duplicate entry → 409 ❌ (actual es 400)

   - Database error → 500 ❌ (actual es 400)

### Manejo Actual en Repository

En `repository.go` (línea 82-86):

```go
if err != nil {
  if err.Error() == "Error 1062: Duplicate entry" {  // ← Detección parcial
    return nil, NewError("conteo_duplicado", "ya existe un conteo para esta tienda, tipo y horario en esta fecha")
  }
  return nil, fmt.Errorf("error creando inventario: %w", err)
}

```text

**Problema**:

- La comparación de string es frágil (depende del formato exacto del mensaje MySQL)

- Si el mensaje cambia (ej: idioma MySQL), la detección falla

- El handler no chequeaba este error específico antes de retornar 400

## Solución Recomendada

### Paso 1: Mejorar Detección de Duplicate en Repository

**Archivo**: `loopi-api-v2/internal/inventarios/repository.go`

**Cambio en CreateInventario** (línea 82-86):

```go
if err != nil {
  if strings.Contains(err.Error(), "1062") && strings.Contains(err.Error(), "uq_inventarios") {
    return nil, NewError("conteo_duplicado",
      "Ya existe un conteo en progreso para esta tienda, tipo y horario hoy")
  }
  return nil, fmt.Errorf("error creando inventario: %w", err)
}

```text

**Por qué**:

- `1062` es el código MySQL de UNIQUE constraint

- `uq_inventarios` especifica cuál constraint falló

- Más robusto que comparación de string exacto

### Paso 2: Mapear Error a HTTP 409 en Handler

**Archivo**: `loopi-api-v2/internal/inventarios/handler.go`

**Cambio en PostInventario** (línea 69-76):

```go
resp, err := h.service.Iniciar(ctx, &req, userID, roleID)
if err != nil {
  h.logger.ErrorContext(ctx, "inventario.iniciar.post: error", "error", err.Error(), "tienda_id", req.TiendaID)

  // Mapear error específico a HTTP 409
  if strings.Contains(err.Error(), "conteo_duplicado") {
    h.respondError(w, http.StatusConflict, "conteo_duplicado",  // ← 409 en lugar de 400
      "Ya existe un conteo en progreso para esta tienda, tipo y horario en esta fecha")
    return
  }

  // Otros errores quedan como 400
  h.respondError(w, http.StatusBadRequest, "error", err.Error())
  return
}

```text

### Paso 3: Mejorar Manejo de Error en Frontend

**Archivo**: `loopi-web-v2/src/app/inventario/inventario-conteo.component.ts`

En el método `iniciarConteo()` (línea 114-120):

```typescript
error: (err) => {
  console.error('Error al iniciar conteo:', err);
  if (err.status === 409 && err.error.error === 'conteo_duplicado') {
    this.confirmationError = err.error.mensaje || 'Ya existe un conteo activo para hoy';
  } else {
    this.confirmationError = err.error?.mensaje || 'Error al iniciar conteo';
  }
}

```text

**Resultado**:

- Error 409 Conflict con error code `conteo_duplicado`

- Mensaje claro al usuario

- Spec contracts/api.md cumplido ✅
