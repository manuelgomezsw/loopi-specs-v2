# Bug Report: BUG-020 — Valores Negativos en Conteo de Inventario

**Type**: Spec gap  
**Severity**: High  
**Feature**: 009-inventario-conteo  
**Reported**: 2026-07-19  
**Status**: ✅ Patched  
**Patched**: 2026-07-19  

---

## Descripción

Durante el registro de conteo físico item por item, el usuario puede ingresar valores negativos en el campo "valor real". El sistema actualmente **no valida ni rechaza** estos valores, lo cual abre una puerta a prácticas fraudulentas:

- Un usuario malintencioando podría registrar "-1000" en una bebida popular, generando un "faltante" artificial que justificaría una merma falsa.
- Los valores negativos no tienen sentido lógico en un conteo físico (cantidad contada debe ser ≥ 0).
- Violación de control interno: el sistema debe garantizar que solo cantidades positivas o cero sean registradas.

**Flujo afectado**:

1. Usuario inicia conteo (POST /inventarios → 201 OK)
2. Usuario ingresa valor real: **-500 ml** ← ACEPTADO (incorrecto)
3. Sistema calcula diferencia: −500 − 5000 (esperado) = −5500 ml
4. Usuario confirma → Stock se ajusta a −500 ml ← **INACEPTABLE**

**Affected Requirements**:

- **RF-INV-02.1**: Define qué se muestra (nombre del item, valor esperado, campo para ingresar valor real) **pero NO especifica restricciones de entrada**

- No existe restricción a nivel de entrada (HTML input type) ni backend validation

## Root Cause Analysis

**Why this bug exists**:

1. **Spec gap**: Requisito RF-INV-02 asume implícitamente que los valores ingresados son positivos, pero no lo explicita
2. **No validación de entrada**: El handler/service actual no valida `valor_real >= 0` antes de guardar
3. **Frontend sin restricción**: El campo de input HTML probablemente es `type="number"` sin atributo `min="0"`, permitiendo valores negativos en navegadores sin restricción

**This is a control-internal violation**: Toda cantidad contada en inventario debe ser no-negativa por definición física.

## Recommended Fix

### Paso 1: Actualizar spec.md

Agregar a RF-INV-02.1 una restricción explícita:

```markdown
- RF-INV-02.1: ... El valor real debe ser un número entero o decimal >= 0 (no se aceptan cantidades negativas).
  Si el usuario intenta ingresar un valor negativo, el sistema retorna HTTP 400 `valor_invalido` con
  mensaje: "La cantidad no puede ser negativa. Ingrese un valor >= 0."
```

### Paso 2: Ejecutar `/speckit-bugfix-patch`

- Actualizar RF-INV-02.1 + Escenarios HU2 con validación explícita
- Agregar a plan.md → Responsabilidades por Capa → Service: validar rango
- Crear T061-ext + T062-ext en tasks.md

### Paso 3: Aplicar patch en código

**Backend (Go)**:

```go
func (s *Service) RegistrarValor(ctx, inventarioID, itemID string, valorReal decimal.Decimal) error {
  // Validar que valor_real >= 0
  if valorReal.LessThan(decimal.Zero) {
    return NewError("valor_invalido", "La cantidad no puede ser negativa")
  }
  // ... continuar con actualización
}
```

**Frontend (Angular)**:

```typescript
this.formGroup.get('valorReal').setValidators([
  Validators.required,
  Validators.min(0)  // ← Rechaza negativos
]);
```
