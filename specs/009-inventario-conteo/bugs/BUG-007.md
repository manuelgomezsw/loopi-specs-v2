# Reporte de Bug: HTTP Status Codes Incorrecto — Todos los Errores Retornan 400

**Tipo**: Implementation drift

**Severidad**: 🔴 Critical

**Feature**: 009-inventario-conteo

**Reportado**: 2026-07-13

**Status: ✅ Patched

**Patched**: 2026-07-13

---

## Descripción

**Todos los endpoints retornan HTTP 400 indiscriminadamente**, sin mapear el error de negocio al status code apropiado.

**Problema**:

```go
// handler.go línea 74, 117, 156, 184, 214, 243
h.respondError(w, http.StatusBadRequest, "error", err.Error())  // ← 400 siempre

```text

### Ejemplos de Mapeo Incorrecto

| Error de Negocio | Status Actual ❌ | Status Correcto ✅ | Impacto |
|---|---|---|---|
| Inventario no existe | 400 | **404 Not Found** | Cliente no distingue entre "datos malformados" vs "recurso no existe" |

| Conteo duplicado (RF-INV-01.4) | 400 | **409 Conflict** | Cliente no puede diferenciar (ver BUG-004) |

| Items sin registrar (RF-INV-03.1) | 400 | **422 Unprocessable Entity** | Status dice "puedo procesar" cuando en realidad está incompleto |

| Conteo bloqueado por otro usuario (RF-INV-02.5) | 400 | **423 Locked** o **403 Forbidden** | Cliente no sabe si es error de autorización |

| Usuario sin permiso (RBAC) | 400 | **403 Forbidden** | Breach de seguridad/UX |

| Admin puede modificar completado (RF-INV-03.3) | 400 | Retorna 200 OK (no es error) | Confuso |

## Análisis de Causa Raíz

En `handler.go`, todos los endpoints hacen:

```go
if err != nil {
  h.respondError(w, http.StatusBadRequest, "error", err.Error())  // ← Siempre 400
  return
}

```text

No hay diferenciación entre:

- Validation error (400 Bad Request) ✓ Correcto

- Not found (404 Not Found) ✗ Actual: 400

- Duplicate (409 Conflict) ✗ Actual: 400

- Unprocessable (422 Unprocessable Entity) ✗ Actual: 400

- Forbidden (403 Forbidden) ✗ Actual: 400

### Patrón Correcto en Items

**Items/handler.go** (línea 480-519) tiene función `mapServiceError()`:

```go
func mapServiceError(err error) (int, *ErrorResp) {
  switch {
  case errors.Is(err, service.ErrNotFound):
    return http.StatusNotFound, ...
  case errors.Is(err, service.ErrDuplicate):
    return http.StatusConflict, ...
  case errors.Is(err, service.ErrValidation):
    return http.StatusBadRequest, ...
  default:
    return http.StatusInternalServerError, ...
  }
}

```text

Luego en cada endpoint:

```go
status, errResp := mapServiceError(err)
h.respondError(w, status, errResp.Error, errResp.Message)

```text

## Solución

### Paso 1: Definir Error Types en `errors.go` (nuevo archivo)

```go
package inventarios

import "errors"

var (
  ErrConteDuplicado = errors.New("conteo_duplicado")
  ErrItemsSinRegistrar = errors.New("items_sin_registrar")
  ErrConteoBloqueado = errors.New("conteo_bloqueado")
  ErrNoPermiso = errors.New("sin_permiso")
  ErrEliminacionNoPermitida = errors.New("eliminacion_no_permitida")
)

```text

### Paso 2: Actualizar Service para retornar tipos específicos

En `service.go`, envolver errores:

```go
func (s *Service) Iniciar(...) (*InventarioResp, error) {
  if exists {
    return nil, ErrContoDuplicado  // ← En lugar de genérico error
  }
  ...
}

```text

### Paso 3: Crear Helper en Handler para mapear

```go
func (h *Handler) mapErrorToHTTP(err error) (int, string, string) {
  switch err {
  case ErrContoDuplicado:
    return http.StatusConflict, "conteo_duplicado", "Ya existe un conteo en progreso"
  case ErrItemsSinRegistrar:
    return http.StatusUnprocessableEntity, "items_sin_registrar", "Items sin registrar"
  case ErrConteoBloqueado:
    return http.StatusForbidden, "conteo_bloqueado", "Conteo bloqueado por otro usuario"
  case ErrNoPermiso:
    return http.StatusForbidden, "sin_permiso", "Sin permiso para esta acción"
  default:
    return http.StatusBadRequest, "error", err.Error()
  }
}

```text

### Paso 4: Usar en Cada Endpoint

```go
resp, err := h.service.Iniciar(...)
if err != nil {
  status, errCode, msg := h.mapErrorToHTTP(err)
  h.respondError(w, status, errCode, msg)
  return
}

```text
