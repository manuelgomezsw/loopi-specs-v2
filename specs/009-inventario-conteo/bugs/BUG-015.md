# BUG-015: Reanudación de Inventario - Falta Validación de Responsable y Lógica de Decisión en UI

**Type**: Implementation drift + Untested flow  
**Severity**: High  
**Feature**: 009-inventario-conteo  
**Reported**: 2026-07-18  

## Descripción

**Problema 1 - Backend sin validación de responsable:**

- User A inicia conteo en tienda 1
- User B (misma tienda 1) intenta reanudar ese conteo
- Backend permite (solo valida tienda, no responsable)
- Resultado: User B puede registrar valores en conteo de User A ❌

**Problema 2 - Frontend sin lógica de decisión:**

- User B hace clic "Iniciar Conteo"
- Backend retorna 409: "Ya existe un conteo en progreso para esta tienda, tipo y horario"
- Frontend muestra error genérico "No se pudo iniciar el conteo. Intenta de nuevo."
- User B NO sabe que User A tiene uno activo
- User B NO tiene opción de reanudar si es responsable

## Solución Requerida

### Backend: Validar responsable_id en Buscar()

En `service.go` método `Buscar()`:

- Agregar check: Si user NO es admin Y user NO es `inventario.responsable_id` → retornar 403 `conteo_bloqueado`
- Garantiza que solo el responsable o admin pueden acceder

### Frontend: Lógica de Decisión antes de Iniciar

Flujo nuevo en `inventario-conteo.component.ts` método `iniciarConteo()`:

```text
1. User hace clic "Iniciar Conteo"
2. Component llama getEstadoInventarioActivo(tienda_id) PRIMERO
3. Según respuesta:
   - activo === false → POST /inventarios nuevo
   - activo === true → Mostrar modal: "¿Deseas reanudarlo?"
     * Si user es responsable → Botón "Reanudar" + Botón "Cerrar"
     * Si user NO es responsable → Solo Botón "Cerrar" (informativo)
4. Si elige Reanudar → GET /inventarios/{id} + transicionar a register
   (El backend rechazará si no es responsable con 403)
```

### Frontend: Template Updates

- Agregar modal overlay con mensaje: "¿Deseas reanudarlo?"
- Botón "Reanudar" (llama reanudaConteo)
- Botón "Cerrar" (descartar y volver a select)
