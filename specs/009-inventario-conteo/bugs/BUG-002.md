# Reporte de Bug: Sugerencia Automática de Tipo/Horario No Se Carga

**Tipo**: Implementation drift

**Severidad**: 🟠 High

**Feature**: 009-inventario-conteo

**Reportado**: 2026-07-13

**Status**: ✅ Patched

**Patched**: 2026-07-13

---

## Descripción

Cuando el usuario ingresa a la vista `/inventario/conteo`, se espera que el sistema sugiera automáticamente el tipo de conteo y el horario según la hora actual del servidor. Sin embargo, esto no sucede: el usuario ve formularios vacíos y **debe seleccionar manualmente** tanto el tipo como el horario.

**Comportamiento esperado** (según spec):

- Usuario entra a `/inventario/conteo` → El sistema detecta la hora actual
- Sistema sugiere automáticamente `diario / apertura` (si 06:00–10:59), `diario / mediodía` (si 11:00–14:59), o `diario / cierre` (si 15:00–23:59)
- Los campos en el formulario se pre-rellenan con la sugerencia
- Usuario puede aceptar la sugerencia o cambiarla manualmente

**Comportamiento observado**:

- Usuario entra a `/inventario/conteo` → Ve campos de formulario vacíos
- Ningún valor se pre-rellena automáticamente
- Usuario debe ingresar manualmente tipo y horario

## Análisis de Causa Raíz

### Problemas Identificados

#### 1. Componente Angular No Llama `loadSugerencia()` Automáticamente (Parcial)

En `inventario-conteo.component.ts` (línea 45-54):

```typescript
ngOnInit(): void {
  this.route.queryParams.subscribe(params => {
    const inventarioId = params['inventario_id'];
    if (inventarioId) {
      this.recuperarSesion(parseInt(inventarioId, 10));
    } else {
      this.loadSugerencia();  // ← Se llama aquí
    }
  });
}
```

**Problema**: `loadSugerencia()` se llama, pero si falla (error 404 por BUG-001), entra en el bloque `error:` en línea 63:

```typescript
error: (err) => console.error('Error al obtener sugerencia:', err)
```

El componente **continúa sin valores predeterminados**, dejando los campos vacíos.

#### 2. Servicio Backend No Extrae la Hora Actual

En `handler.go`, línea 30-46:

```go
func (h *Handler) GetSugerencia(w http.ResponseWriter, r *http.Request) {
  ctx := r.Context()
  h.logger.InfoContext(ctx, "inventario.sugerencia.get: iniciando")

  sugerencia, err := h.service.Sugerir(ctx)  // ← Llama service.Sugerir(ctx)
  if err != nil {
    h.respondError(w, http.StatusBadRequest, "error", err.Error())
    return
  }
  h.respondJSON(w, http.StatusOK, sugerencia)
}
```

Se espera que `service.Sugerir(ctx)` implemente la lógica de hora actual. **Necesitamos verificar si esta lógica está implementada correctamente en `service.go`.**

#### 3. Posible Problema en Frontend: Error Recovery

Incluso si el endpoint funciona, si `GET /sugerencia` falla:

- La sugerencia no se carga
- Los campos `formData.tipo` y `formData.horario` quedan vacíos (`''` y `undefined`)
- El usuario ve un formulario vacío sin explicación

**No hay fallback**: El componente debería mostrar valores predeterminados o un mensaje indicando que la sugerencia no pudo cargarse.

#### 4. Interfaz No Refleja Estado de Carga

El componente no tiene indicadores visuales:

- No hay spinner o estado "Cargando sugerencia..."
- No hay mensaje de error visible al usuario
- El usuario no sabe si la sugerencia falló o simplemente no existe

## Impacto

- **Experiencia de usuario degradada**: El usuario debe ingresar manualmente valores que el sistema debería sugerir
- **Contratos de aceptación no verificables**: El escenario "sistema sugiere diario/apertura" no se puede probar
- **Reduce velocidad de conteo**: RF-INV-02.2 especifica "Velocidad de conteo: El líder puede completar un conteo diario de hasta 50 items en menos de 15 minutos" — si el usuario gasta tiempo ingresando tipo/horario, la velocidad disminuye
- **Dependencia de BUG-001**: Si el endpoint sigue retornando 404, `loadSugerencia()` nunca recibe datos

## Causas Principales (Hipótesis Ordenadas por Probabilidad)

1. **BUG-001 aún no está resuelto**: Endpoint `/api/v1/inventarios/sugerencia` retorna 404 → `loadSugerencia()` entra en error → Formulario no se pre-rellena
   - **Evidencia**: Los logs muestran 404 en la consola
   - **Solución**: Aplicar BUG-001 fix primero

2. **Error recovery deficiente en componente**: Aunque el endpoint funcione, si hay error temporal, el componente no maneja gracefully
   - **Evidencia**: No hay valores por defecto si `getSugerencia()` falla
   - **Solución**: Agregar fallback (ej: tipo = 'diario', horario = null)

3. **Lógica de `Sugerir()` en service.go no está completa**: Posible que el método no calcule la hora actual correctamente
   - **Evidencia**: Solo verificable después de que BUG-001 está resuelto
   - **Solución**: Implementar lógica de hora en el servicio Go

## Solución Recomendada

### Paso 1: Resolver BUG-001 Primero

Ejecutar `/speckit-bugfix-patch` para registrar endpoints en main.go. Sin esto, `GET /sugerencia` seguirá retornando 404.

### Paso 2: Verificar Lógica de `Sugerir()` en Backend

En `loopi-api-v2/internal/inventarios/service.go`, verificar que exista y esté implementado:

```go
func (s *Service) Sugerir(ctx context.Context) (*SugerenciaResp, error) {
  now := time.Now()
  hour := now.Hour()

  var sugerencia SugerenciaResp
  sugerencia.Tipo = "diario"

  if hour >= 6 && hour < 11 {
    sugerencia.Horario = "apertura"
  } else if hour >= 11 && hour < 15 {
    sugerencia.Horario = "mediodia"
  } else if hour >= 15 && hour < 24 {
    sugerencia.Horario = "cierre"
  } else {
    sugerencia.Horario = "cierre" // Fallback para 00:00-05:59
  }

  return &sugerencia, nil
}
```

### Paso 3: Agregar Error Recovery en Frontend

En `inventario-conteo.component.ts`, actualizar `loadSugerencia()`:

```typescript
loadSugerencia(): void {
  this.inventarioService.getSugerencia().subscribe({
    next: (data) => {
      this.sugerencia = data;
      this.formData.tipo = data.tipo;
      this.formData.horario = data.horario;
    },
    error: (err) => {
      console.error('Error al obtener sugerencia:', err);
      // Fallback: sugerir 'diario' sin horario si la API falla
      this.formData.tipo = 'diario';
      this.formData.horario = undefined;
      // Opcional: mostrar toast indicando que se usaron valores por defecto
    }
  });
}
```

### Paso 4: Agregar Indicador Visual

Actualizar template HTML para mostrar estado de carga:

- Agregar spinner mientras se carga sugerencia
- Mostrar mensaje si falla ("No se pudo cargar sugerencia, ingrese manualmente")
