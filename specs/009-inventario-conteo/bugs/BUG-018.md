## Descripción del Bug

Actualmente, el indicador visual de diferencias en la esquina superior derecha de la tarjeta de item usa el patrón:

```text
'⚠️ Pérdida' : '✓ Ganancia'
```

**Problemas identificados**:

1. **Ambigüedad conceptual**: Los términos "Pérdida" y "Ganancia" usan connotaciones emocionales (malo/bueno) cuando en realidad son observaciones operativas neutras sobre discrepancias de conteo
2. **Confusión con símbolos**: El símbolo `✓` (checkmark/éxito) aparece para "Ganancia" (que IS una discrepancia) cuando debería reservarse para diferencia = 0 (correcto)
3. **No comunica contexto**: El operador puede confundir "Pérdida" con "Error" o "Fallo" cuando debería entender que es simplemente una diferencia que debe reportarse al administrador
4. **Inconsistencia con RF-INV-02.3**: El requisito define color (rojo/verde/gris) pero no define explícitamente qué MENSAJE corto debe acompañar ese color en la etiqueta

**Ejemplos de confusión**:

- **Item Almojabana**: Sugerido=10, Contado=2, Diferencia=-8
  - Patrón actual: `⚠️ Pérdida` (parece alerta de error)
  - Debería ser: Un mensaje que diga "Faltante: -8 unidades" o "Diferencia: -8" para que el operador entienda qué preguntar al administrador

- **Item Aromática**: Sugerido=12, Contado=14, Diferencia=+2
  - Patrón actual: `✓ Ganancia` (parece éxito)
  - Debería ser: Un mensaje que diga "Exceso: +2 unidades" o "Diferencia: +2" para que el operador entienda que hay items demás

- **Item Palito de Queso**: Sugerido=8, Contado=8, Diferencia=0
  - Patrón actual: Implícito (sin etiqueta visual clara)
  - Debería ser: "Correcto" o "✓" para confirmar que el conteo es exacto

## Root Cause Analysis

1. **Diseño UX incompleto en spec**: RF-INV-02.3 define **cómo** mostrar (color, símbolo, número) pero no **qué texto** usar para etiquetar la discrepancia de forma clara y no ambigua

2. **Implementación sin validación**: Las tasks T041/T042 implementaron el indicador pero sin directiva clara del spec, resultando en patrón "'⚠️ Pérdida' : '✓ Ganancia'" que causa confusión

3. **Terminología ambigua**: "Pérdida" y "Ganancia" son términos que el sector retail podría entender, pero en contexto de conteo físico son confusos porque:
   - Una "pérdida" de 8 unidades no significa que se perdieron (pueden estar mal contadas, mal ubicadas, etc.)
   - Una "ganancia" de 2 unidades no es una ganancia (pueden ser encontradas, etc.)

## Recomendación de Solución

Actualizar **RF-INV-02.3 en spec.md** para definir explícitamente el patrón de mensaje/etiqueta con las siguientes opciones:

### Opción A: Terminología Operativa (Recomendada)

Usar términos que describan el estado del conteo sin connotaciones emocionales:

| Diferencia | Mensaje | Color | Símbolo | Ejemplo |
|-----------|---------|-------|---------|---------|
| < 0 | `Faltante` | Rojo | ⚠️ | "⚠️ Faltante: -8" |
| > 0 | `Exceso` | Verde | ℹ️ | "ℹ️ Exceso: +2" |
| = 0 | `Correcto` | Gris | ✓ | "✓ Correcto" |

**Ventajas**:

- "Faltante" comunica "hay menos de lo esperado" (causa = conteo incompleto o mal ubicado)
- "Exceso" comunica "hay más de lo esperado" (causa = conteo incompleto o encontrado)
- "Correcto" comunica "concordancia perfecta"
- Todos son términos neutrales, no implican culpa o éxito

### Opción B: Minimalista (Alternativa)

Usar solo el valor numérico + color + símbolo (sin etiqueta de texto):

| Diferencia | Formato | Color | Símbolo |
|-----------|---------|-------|---------|
| < 0 | `-8 unidades` | Rojo | ⚠️ |
| > 0 | `+2 unidades` | Verde | — |
| = 0 | `0` | Gris | ✓ |

**Ventajas**:

- Máxima claridad: el número habla por sí solo
- Menos texto = mejor en mobile
- El símbolo ⚠️ solo aparece cuando hay diferencia
