# BUG-013: GetSugerencia — Panic por Type Assertion en Context sin Validación

**Type**: Implementation drift  
**Severity**: Critical  
**Feature**: 009-inventario-conteo  
**Reported**: 2026-07-18  
**Discoverer**: Manuel Gomez  

## Descripción

Al iniciar un conteo de inventario, el inventario se crea correctamente en la BD:

```sql
id: 7, tienda_id: 1, tipo: diario, horario: apertura, 
estado: en_progreso, responsable_id: 1, iniciado_en: 2026-07-18 15:26:16
```

Pero la API responde con un **panic**:

```text
http: panic serving [::1]:55076: interface conversion: interface {} is nil, not *auth.Claims
goroutine 145 [running]:
...
github.com/manuelgomezsw/loopi-api-v2/internal/inventarios.(*Handler).GetSugerencia
    /internal/inventarios/handler.go:79 +0x625
```

## Root Cause Analysis

**Conflicto entre intención y implementación:**

**Intención del API** (handler.go:702-703):

- La ruta NO está protegida por middleware de autenticación.

```go
// GET /api/v1/inventarios/sugerencia — público (no requiere autenticación)
mux.HandleFunc("GET /api/v1/inventarios/sugerencia", h.GetSugerencia)
```

**Implementación del handler** (handler.go:77-80):

- El handler hace type assertion directa a `*auth.Claims` **sin verificar si es nil** antes de usarlo.

```go
func (h *Handler) GetSugerencia(w http.ResponseWriter, r *http.Request) {
    ctx := r.Context()
    claims := ctx.Value(auth.ContextKeyClaims).(*auth.Claims)  // ← PANIC AQUÍ
```

**El problema**:

- Cuando se llama sin autenticación, `ctx.Value(auth.ContextKeyClaims)` retorna `nil`
- Esto causa un panic en la type assertion

## Comparación con Otros Handlers

Otros handlers (ej: `PostInventario`, `GetInventario`) **verifican** si claims es nil:

```go
// handler.go:119-125 (PostInventario) — CORRECTO
claims := ctx.Value(auth.ContextKeyClaims).(*auth.Claims)
if claims == nil {
    h.logger.WarnContext(ctx, "inventario.iniciar.post: unauthorized",
        "reason", "no JWT claims found")
    h.respondError(w, http.StatusUnauthorized, "unauthorized", "Token JWT inválido")
    return
}
```

## Traceabilidad a Artefactos

### spec.md

- **Affected user story**: Historia de Usuario 1 — Iniciar un conteo de inventario (P1)
- **Affected requirement**: "El sistema sugiere el tipo y horario según la hora del día"
  - Línea 14-30: La sugerencia es **basada en la hora actual del servidor**, independiente del usuario
  - La especificación NO indica que requiera autenticación para obtener la sugerencia

### handler.go

- **Current state**: Endpoint registrado como público (línea 703)
- **Implementation state**: Handler asume autenticación obligatoria (línea 79)
- **False assumption**: Desarrollador agregó logging de user_id/rol/tienda_id esperando autenticación, pero no protegió la ruta

### plan.md

- **T143**: GetEstadoInventarioActivo — requiere autenticación y está CORRECTAMENTE protegido con middleware
- **T029**: PostInventario — requiere autenticación y está CORRECTAMENTE protegido con middleware
- **GetSugerencia** NO está en tasks pero está en el flujo de UI (inventario-conteo.component.ts:88-95)

## Dos Opciones de Fix

### Opción A: GetSugerencia ES público (sin autenticación)

- **Cambio**: Remover intento de acceso a claims
- **Impacto spec**: Alineado — sugerencia basada solo en hora del servidor
- **Impacto código**: Simplifica el handler, no requiere auth context
- **Recomendado**: ✅ SÍ — Alineado con especificación

### Opción B: GetSugerencia REQUIERE autenticación

- **Cambio**: Agregar middleware de auth a la ruta (línea 703)
- **Impacto spec**: Requiere actualizar spec para indicar que sugerencia requiere autenticación
- **Impacto código**: Handler se mantiene igual (accede a user_id/rol/tienda_id)
- **Recomendado**: ❌ NO — Contradice especificación

## Recommended Fix

1. **Fix inmediato** (Opción A — alineado con spec):
   - Remover acceso a claims en `GetSugerencia`
   - El endpoint retorna sugerencia basada **solo en la hora actual del servidor**
   - No requiere loguear user_id/rol/tienda_id porque no depende del usuario
1. **Commit**:

```text
fix(009): BUG-013 - GetSugerencia - remover type assertion de claims en endpoint público
```

1. **Verificación**:
   - Llamar GET `/api/v1/inventarios/sugerencia` sin Authorization header
   - Debe retornar `{ tipo: "diario", horario: "apertura" }` sin panic
   - Llamar POST `/api/v1/inventarios` con datos válidos debe completarse sin panic después
